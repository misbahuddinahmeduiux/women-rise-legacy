4. ELEMENTOR FREE IMPLEMENTATION STRATEGY
==================================================

Elementor Free does not provide:
- Theme Builder
- Dynamic CPT single templates
- Advanced loops
- Dynamic custom fields
- Full member dashboard builder

Therefore, the architecture is:

- Elementor Free: normal pages and section designs
- Pods: custom post types, taxonomies, and fields
- Content Views: CPT grids and listing pages
- Pods Templates/shortcodes: dynamic single pages
- Forminator: all forms and applications
- GiveWP: financial donations
- BuddyPress: members and community
- bbPress: forums
- Simple Membership: membership access levels
- WP Go Maps: interactive map
- Events Manager: event registration and management
- Members plugin: custom user roles
- Polylang later: multilingual system

14. FREE MVP WORKFLOWS
==================================================

MENTOR MATCHING

Automatic matching will not be used.

Workflow:
1. User browses mentor profiles
2. User submits Forminator mentorship request
3. Admin reviews request
4. Admin manually contacts and assigns mentor
5. Member receives confirmation email

GIVE HOPE MARKETPLACE

Do not use WooCommerce in the first phase.

Workflow:
1. Donor browses Current Needs
2. Donor filters by country/category
3. Donor opens a Current Need
4. Donor clicks external wishlist or retailer link
5. Donor buys the item on Amazon, Walmart, Target, or another retailer
6. Donor ships it to the approved address
7. Donor submits tracking details using Forminator
8. Admin manually updates quantity and status

WOMEN-OWNED MARKETPLACE

Initial MVP will be a directory/catalog, not a real multivendor marketplace.

Display:
- Product image
- Description
- Price
- Seller/business profile
- Contact seller
- Visit seller website
- External purchase link

No:
- Vendor dashboards
- Split payments
- Commissions
- Withdrawals
- Complex shipping
- Marketplace checkout

REQUEST ASSISTANCE

Workflow:
1. Applicant submits Forminator form
2. Admin reviews request
3. Supporting documents are verified
4. Admin approves or rejects
5. Approved request is manually published as Current Need
6. Need receives donations
7. Admin updates status
8. Final impact story/report is published

SPONSOR A FAMILY

Workflow:
1. Family is verified privately
2. Admin creates Sponsor Family CPT
3. Public alias is used
4. GiveWP form is embedded
5. Donations are received
6. Admin updates amount raised
7. Approved impact updates are published

DONATE ITEMS

Workflow:
1. Donor submits Donate Items form
2. Admin checks item suitability
3. Admin sends shipping instructions
4. Donor ships item
5. Donor submits tracking details
6. Admin records shipment
7. Current Need quantity/status is updated
8. Impact update is published
